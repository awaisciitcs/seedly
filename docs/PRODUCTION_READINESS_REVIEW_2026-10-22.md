# Production readiness review - 22 October 2026

## Decision

**The tested fixes are deployed, but unconditional production sign-off is not justified yet.** Commit 65b6fa54c71e926c8d5b8539d2a4444b5f035b87 was deployed successfully and verified on the live server as Next.js 15.5.28. Live URL: https://seedly.softbytes.co.uk. Local patched production preview: http://127.0.0.1:3111. No real customer orders, emails, uploaded receipts, inventory adjustments, migrations or payment-setting changes were made. Two display-copy fields in the site CMS were corrected after capturing complete draft/published backups; revisions 1 through 3 are retained. Temporary OWNER, STAFF and non-admin Auth identities, a zero-stock DRAFT product and a disabled coupon were created for acceptance and removed afterward. Test passwords and sessions were not persisted. Quote/negative checks can increment shared admission counters.

Baseline commit: 6176dc9bc78d631ad834e0fcffe87f027fbb2db6. The existing untracked .github/workflows/quality.yml was preserved. Release source is published through the existing GitHub-to-Vercel integration after acceptance. ## Workflow and security assessment

- **Shopping:** current categories and all active detail pages resolve. Search returns products and images while typing. Sort applies immediately; mobile filters open from the left. Real products appear in routine results. Cart identities, stock caps, disabled/archived pack handling and corrupt-storage handling have regression coverage.
- **Checkout:** live ordering and receipt upload are enabled, with bank transfer as the sole enabled payment method at review time. The server remains the price, coupon, stock and signing authority. Required fields now agree with the API. No live positive purchase was submitted. Direct product/kit reservations, replay recovery, changed requests, stale quotes and coupon limits passed isolated tests.
- **Fulfillment:** payment review and packing remain separate, dispatch requires courier/tracking, terminal orders cannot re-enter processing, and cancellation releases recorded stock once. Historical orders without reservations must still be reconciled. Do not weaken that guard to force cancellation.
- **Administration:** source uses verified Supabase Auth plus active UUID-linked OWNER/STAFF membership, scoped clients and database RLS. Owner-only settings/coupon/content boundaries and revoked-role behavior passed isolated tests. Live anonymous denial was verified. Positive live OWNER/STAFF access, owner-only boundaries, non-admin metadata spoof rejection, forbidden writes and immediate disabled-membership rejection passed using disposable test identities. Local browser acceptance also covers login, protected navigation, mobile layout, logout failure recovery and successful logout.
- **Customer data:** private response caching, capability-protected sequential order links, no-referrer order pages, input limits, CSV formula neutralization and receipt URL access were reviewed. Anonymous identity reads stayed closed in the live checks. This is not a full forensic review of historical access or a certificate that no vulnerabilities exist.
- **Content/reviews:** draft and publication conflicts, role boundaries, private revisions, invalid edits and review moderation boundaries have isolated coverage. Only the two documented site display-copy fields were published; no products, review content or other CMS document values were modified. A version-checked positive live publication was exercised, with before/after field comparisons and temporary-identity cleanup.
- **Analytics/leads:** both optional providers are currently disabled in the live public settings. The browser sent no optional-provider SDK/event requests before consent. Existing tests cover consent scope, withdrawal, masking/exclusions, identifiers and private lead access. Actual provider ingestion cannot be accepted while providers are disabled. Expired lead physical deletion remains submission-triggered or owner-triggered; there is no scheduled purge in this release.
- **Notifications:** durable order queue, lease recovery, frozen provider keys/bodies, bounded retries and uncertain-send protection passed fixture tests. The deployed OWNER diagnostic confirms provider_configured=false and worker_authorization_configured=false, as well as incomplete configuration overall. The local provider/key is also absent. No worker was invoked to send existing queued customer messages; delivery, scheduler and bounce handling remain unverified. Restock delivery remains preparation-only.

## UI, layout and performance

The desktop header, clear primary purchase actions, mobile bottom navigation, left filter drawer and two-column mobile product grid form a consistent shopping path. Screenshots were inspected. Tested routes fit at 390 px; key pages also fit at 320 px and desktop 1440 px without document-level horizontal overflow. This is Chromium emulation, not physical Safari/iOS/Android acceptance or a complete WCAG audit.

The admin fixes remove false operational numbers and make the customer/order controls useful while preserving the existing theme. Data-heavy admin tables intentionally scroll within their containers. Authenticated desktop navigation and a 390 px admin viewport were exercised with a disposable OWNER session. Wider device and accessibility acceptance remains a separate release activity.

Build-reported first-load JavaScript is approximately 202 KiB on home, 205 KiB on shop and 203 KiB on checkout; shared application JavaScript is about 103 KiB. Optional analytics remains lazy and consent-controlled. No heavy 3D dependencies were added.

Initial live storefront HTML fetch samples ranged roughly from 0.9 to 5.5 seconds from this environment. These are network/server-response samples, not real-user LCP/INP/CLS scores or a load-test result. Before wider traffic:

1. Measure real-user Core Web Vitals on mobile networks and trace slow server/database reads.
2. Replace full-history dashboard/customer materialization with database aggregates and true server-side result pagination as history grows. Current batched reads prevent omissions but still transfer history to authenticated views.
3. Maintain responsive image sizing, reduced-motion support and lightweight CSS interactions; defer optional third-party scenes/scripts until measured against conversion and mobile performance.
4. Add hosted error, latency, stock-conflict, rejected-payment and notification-failure monitoring with actionable alerts.
